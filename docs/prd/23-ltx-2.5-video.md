# PRD 23 — LTX-2.5: every input combination for video (and audio)

Status: **implemented on `feat/ltx25-video`**, served from a2's 4090 (home lab), 2026-11-08.

## Why

LTX-2 (the `ltx-2` model behind `/v1/videos/generations`) did one thing:
prompt (+ optional first frame) → a short MP4. LTX-2.5 (Lightricks, Oct 2026,
22B DiT + Gemma-4 12B text encoder) is a joint **audio+video** world model whose
open pipelines take almost any combination of text, images, audio and video:

| Mode | Inputs | Output | `ltx_pipelines` module | Checkpoint |
|---|---|---|---|---|
| text-to-video (+ synced audio) | prompt | MP4 w/ audio | `distilled` / `dfr_pipeline` (hq) | distilled |
| **multishot** (new in 2.5) | prompt describing several shots | one MP4, cuts, consistent characters/voice | same | distilled |
| image-to-video | prompt + first frame | MP4 | `distilled --image p 0 s` | distilled |
| **keyframes** | prompt + images at any frames (first/last/…) | MP4 interpolating them | `distilled --image p N s` | distilled |
| **audio-to-video** | prompt + audio (+ image) | MP4 driven by the track (lip-sync, beats) | `a2vid_two_stage` | dev + distilled LoRA |
| **video-to-video** | prompt + source video + IC-LoRA | restyled MP4, same motion/framing | `ic_lora` | distilled |
| **retake** | source video + time range + prompt | same video, that range regenerated | `retake` | distilled |
| **text-to-audio** | prompt | WAV only | `t2a_one_stage` | dev |
| dub / HDR / alpha | video (+ reference) | dubbed / HDR / matte | `dubit`, `hdr_ic_lora`, `alpha_gen` | distilled |
| auto duration (new) | prompt | the duration head picks the length | `--duration-head-path` | distilled |
| prompt enhancer (new) | short prompt | expanded cinematic prompt | `--enhance-prompt` | — |

Official IC-LoRAs (video→video) for 2.5: Day-to-Night, Colorization,
Ingredients (reference sheet → consistent characters/props), Layout-to-Render
(3D blockout → final shot), Clean-Plate, Deblur, Decompression, Restore,
Water-Simulation, Pixel-Spatial-Upscaler (DFR's detailer), Alpha-Gen, SDR→HDR.
Plain LoRAs: Cinemagraph, Slow-Motion. Most LTX-2.3 LoRAs (Union Control =
canny+depth+pose, Relight, Foley V2A, DubIt, In/Outpainting) load on 2.5.

## API (backward compatible)

`POST /v1/videos/generations` keeps every LTX-2 field and adds, all optional:

```jsonc
{
  "model": "ltx-2.5",
  "prompt": "…",
  "mode": "auto",                 // t2v|i2v|keyframes|a2v|v2v|retake|t2a|v2a — auto infers from inputs
  "image": "asset:Jl2ken-RoU8",   // first frame; now also accepts an asset reference
  "images": [                      // keyframes (≤ 8)
    {"image": "asset:gkpi22_ILHk", "position": "first"},
    {"image": "data:image/png;base64,…", "position": "last", "strength": 0.9},
    {"image": "https://…", "frame": 48}
  ],
  "audio": "asset:H59c2ZQQQqg",   // audio-to-video: an ACE-Step song, a Dia voice, an upload
  "audio_start_time": 0,
  "video": "asset:…",             // source for v2v / retake
  "video_strength": 1.0,
  "lora": "day-to-night", "lora_strength": 1.0,
  "retake_start": 1.5, "retake_end": 3.0,
  "quality": "fast",               // fast = distilled 8-step · hq = DFR detailing pass
  "auto_duration": true            // omit duration → the duration head chooses
}
```

**Asset references are the synergy.** Any media field may be `"asset:<public_id>"`
(or `{"asset": "<public_id>"}`): the backend checks visibility, inlines the bytes
upstream, records the reference in `payload.inputs` (no base64 is ever persisted),
and links the output's `derived_from` — so a FLUX image → LTX keyframe, an
ACE-Step song → a music video, a Dia line → a talking portrait, a video → its
night-time retake are all one call and the provenance graph shows the chain.
Inline inputs are stored as `INPUT_IMAGE` / `INPUT_AUDIO` / `INPUT_VIDEO` assets
on the request so retries/async jobs replay faithfully.

Output: `video/mp4` (with an audio track) or `audio/wav` for `t2a` (stored as
`OUTPUT_AUDIO`). `X-LTX-Params` carries the resolved mode, seed, size, frames,
fps, duration, LoRA and timing; `X-Request-Id` the stored request.

Other backend changes:
- `VIDEO_UPSTREAM_TIMEOUT_SECONDS` (default 900) — video jobs on a 24 GB card
  run minutes; the shared 300 s timeout cut them off. The agent allows 10 min.
- `DATA_UPLOAD_MAX_MEMORY_SIZE` raised to 112 MB (env) — inline base64 media in
  JSON otherwise trips Django's 2.5 MB `RequestDataTooBig`.

## Playground

`/dashboard/playground/videos` shows a **More inputs** panel when the selected
model advertises the features (`keyframes`, `audio-to-video`, `video-to-video`,
`retake`, `loras`, `text-to-audio`, `auto-duration` in the Service
`inference-club.com/models` annotation):
- End frame (upload / existing image) → keyframe interpolation.
- Audio — upload or **pick from your music/voice generations** (`MediaAssetPicker`).
- Source video — upload or pick one of your videos; *Restyle* with an IC-LoRA or
  *Retake* a time range.
- LoRA (cinemagraph, slow-motion) + strength; Quality (fast/hq); Auto duration;
  Audio only (t2a).

## Serving (home lab)

See home-cluster `services/ltx25/` — `ltx2-server`'s `ltx_server/ltx25.py`
runs each mode as the official CLI with bf16 weights fp8-cast + CPU offload on
a2's RTX 4090 (24 GB) + 62 GB RAM. Results and timings: home-cluster
`docs/` LTX-2.5 report.

## Follow-ups
- Keep pipelines resident between requests (today each job reloads weights —
  simple and leak-free, but load time dominates short clips).
- Containerize the server; schedule it as a pod with a GPU claim.
- Video-to-audio (Foley LoRA) is exposed as `mode: v2a` but not wired yet.
- Frontend: a timeline for >2 keyframes; "Use as source" / "Retake" buttons on
  video detail pages; render `derived_from` as a provenance strip.
